# DESIGN.md — SDL Map visual canon

The persistent design contract for `sdl-map.discoverylabs.nl`. Read this before any UI change so edits stay coherent. Tokens live in `public/tokens.css` (single source, shared by the Astro shell and the iframe map). Do not redefine colours, type, or surfaces inline.

## Voice
Restrained editorial, not a dashboard and not a marketing page. It is a curated reference map for a serious scientific-infrastructure audience (NWO LSRI, PIs, funders). Calm dark canvas, generous spacing, monospace for metadata, sans for content. No gradients-as-decoration, no glassmorphism, no drop-shadow stacks, no animated flourish that does not carry meaning. When in doubt, remove.

## Colour (tokens, `public/tokens.css`)
Dark is the default; `[data-theme="light"]` overrides the same token names. All colours are `oklch` for perceptual consistency across themes.

- Surfaces: `--bg` (canvas), `--bg-2` (cards/inputs), `--bg-3` (hover), plus `--surface-overlay` / `--surface-deep` / `--surface-hover` for sheets and popups.
- Ink (text): `--ink` (primary), `--ink-2` (secondary), `--ink-3` (muted/labels), `--ink-4` (faint).
- Lines: `--rule` (borders), `--rule-2` (subtle). Map geography: `--land`, `--land-edge`, `--graticule`.
- Tier accents (the only saturated colours; one per SDL category, never reused for UI chrome):
  - `--c-national` gold · `--c-academic` blue · `--c-commercial` red · `--c-labos` violet.
- **Canvas borders** are themed tokens (`--map-border`, `--map-coast`, `--map-province`), read by the map like the other canvas colours. Dark was raised 2026-09-21 (0.32 → 0.44 / 0.54 / 0.42 on 0.24 land) because the borders read as almost nothing; light is unchanged from the previous hard-coded strokes (0.32 / 0.40 / 0.30).

## Type
- Sans: **Inter** (variable, weights 400–700). Body and headings.
- Mono: **IBM Plex Mono** (400/500/600). Labels, eyebrows, stats, counts, datestamps, footer.
- Both are self-hosted (`public/fonts/`, declared in `public/fonts.css`). No Google Fonts CDN — keeps visitor IPs off third parties (EU privacy) and avoids a render-blocking external request.
- Uppercase + letter-spacing (~0.16–0.22em) for mono eyebrows/labels. `font-variant-numeric: tabular-nums` for stat figures.

## Layout
- One visible viewport on the map view: header + map + footer add up to `100svh`/`100dvh` (mobile URL-bar aware), no page scroll.
- Header collapses to a hamburger drawer below 1024px; stat chips drop below 1100px first.
- List/timeline pages: centered `max-width:1100px` column; responsive card grid `minmax(260px,1fr)`.

## Accessibility
- Pinch-zoom must stay enabled. The viewport meta is `width=device-width, initial-scale=1.0, viewport-fit=cover` only. Never add `user-scalable=no` or `maximum-scale`.
- Keep tier-colour meaning backed by text labels (colour is never the only signal).

## Architecture invariants
- **One dataset.** `src/data/sdl_data.json` is the single source of truth. The Astro pages import it directly; the iframe map loads it via the generated `/sdl-data.js` endpoint. Never hand-maintain a second copy inside `map-legacy.html`.
- **No third-party runtime origins.** d3, topojson, the world/China geo data, and the fonts are all vendored under `public/vendor/` and `public/fonts/`. The site must work behind a firewall and inside China.
- **i18n at build where possible.** UI strings come from `src/i18n/`. The Simplified→Traditional dictionary is built once at build time (UnifiedLayout frontmatter), not per page load.
- **Tokens are shared.** Any new colour/type/surface goes in `public/tokens.css`, used by both the shell and the iframe. No inline hex/oklch in components.

## Anti-patterns (do not introduce)
Glassmorphism as decoration (see § Glass for the one permitted material), neon glows, card-with-left-border-accent callouts, multiple competing border styles in one view, decorative gradients, motion without meaning, Google Fonts or any CDN dependency, a second copy of the SDL data.

## The map — pins, discs and controls (2026-09-20 redesign)
Pins are cut from ONE hierarchical tree (`public/map-clusters.js`, agglomerative, centroid linkage, built once) at a distance that tracks zoom continuously: 30 CSS px on desktop, 36 on touch, with a 6 % dead band. A disc splits into its members with a 250 ms travel-and-fade; the same DOM nodes persist, nothing pops. Rules:
- **One size law.** Leaf pin radius 5 px desktop / 6.5 px touch (×1.3 when highlighted), 2 px canvas-colour stroke. No investment sizing, no zoom-dependent growth, no per-frame force push.
- **Discs carry density as size**: diameter 24 + 1.2·min(n, 20) px (+2 on touch), `--bg-2` fill, `--rule` stroke, count in mono, tier mix as a thin segmented ring in the tier accents (the only place the accents appear on a disc). Filters recount discs and dim the empty ones. Hover shows a summary tip; click or tap flies in until the disc separates.
- **Same-campus groups** (closer than the threshold reachable at k 40 desktop / k 60 touch) fan out on a ring around their centroid, because no zoom could ever separate them. **No lines (2026-09-21):** the group is shown as one quiet ring (`.spider-ring`, ink-3 at 0.38, 0.75 px) with a small mark at the true spot (`.spider-core`), pins on the rim and names radiating outward. The earlier leg per pin and the leader line from a dot to a displaced name crossed each other and the text at small radii (six crossings in the Netherlands at k 60); both are gone. A name now lives beside its dot or not at all: if relaxation pushes its box more than a line height off the dot, it is hidden rather than tethered.
- **Names follow an area budget** (`labelBudget`: one per ~36k CSS px², 42k on touch, clamped 6–28; zero at world zoom on touch), rank by tier then investment, get a 3 px canvas-colour halo, and treat discs as obstacles.
- **Phones start and fly a third closer** than desktop for the same region, and cannot zoom out past k 2 (globe fills the width).
- **Controls, desktop:** one vocabulary — 36 px squares, `--r-soft`, the glass surface, 1 px edge — for the top-left row (about · clear · export · data at a 44 px pitch), the zoom column (five separate squares with SVG icons at a 6 px gap, no box, no dividers) and the region buttons (bottom-right). `public/map-chrome.css` owns this; it must out-specify the styles export.js and map-i18n.js inject at runtime.
- **Controls, phone (≤ 900 px):** exactly one map button (reset) plus one bottom sheet (`public/map-mobile-sheet.js`): peek 112 px = "N in view" · Filters (k) · region chips; half 52 svh and full 86 svh show the in-view list or the filter groups (the desktop asides' own chip nodes, moved in) with an action row (About · Flat/Globe · Export · Data · Clear). The detail sheet stacks above it. Edge tabs, drawers, floating buttons and the region column do not exist on phones.
- **Verification is numeric before it is visual:** `npm test` (cluster laws) and `npm run qa -- --base <url> --label <name>` (Playwright audit: control count, overlaps, tap sizes, label and pin overlaps, screenshots) run before any map change ships. Gates: zero control overlaps, zero pin overlaps, ≤ 5 persistent phone controls, no labels at world zoom on touch.

- **Geometry while the view changes (v47, 2026-09-20 night):** the 50m atlas is drawn at rest *and* during drag, pinch, wheel and flights, so coastlines no longer coarsen under the finger. It is affordable because a moving frame draws only the 50m polygons and border lines whose lon/lat box is in view (per polygon, not per country: France or Norway would otherwise drag their islands along), filled as one path so shared borders leave no seams. Measured headless: 79 ms per frame for the whole atlas, 16 ms culled at the arrival view, 9 ms zoomed in, 5 ms for 110m. Two guards stay: below `HI_MOVE_K` (1.4× the base scale, whole-globe views where 50m detail is sub-pixel) moving frames still use 110m, and three consecutive moving frames slower than `HI_SLOW_MS` (24 ms) fall back to 110m for a cooldown that doubles each time (1.5 s → 30 s), so a weak device pays at most three slow frames per attempt. `window.__sdlGeoStats` counts hi/lo moving frames and cooldowns for the QA scripts; `forceChanging` and `window.__sdlRedraw` let a script draw the moving code path at a static view, and `?diag=1` on the site URL shows a live readout on the device. The settled frame is always the full atlas. Visibility is tested against the canvas's real visible rectangle (`_visBox`, projection units), not the 1000×560 viewBox: a portrait phone shows far above and below that band, and the first cut culled Greenland and North Africa while on screen. The graticule is the same 15° grid moving and settled, and the second fallback of a session disables the 50m-while-moving path for good, so geometry never alternates between gestures. Verified: a frame drawn on the moving path is pixel-identical to the settled frame at 390 and 1440, two zooms each (2026-09-21).

## Glass — Vitrine (owner decision 2026-09-20)
Supersedes the glassmorphism entry in Anti-patterns. What stays forbidden is the templated blurred card with nothing behind it. What is allowed is one named material, **Vitrine**: museum-case glass, cool and thin, one specular edge, for chrome that floats over the *live map* and for the sticky site header that content scrolls under. Nothing else gets it: list, timeline and watch cards, filter chips and the footer stay solid.
- **Tokens** (`public/tokens.css`, both themes): `--glass-bg` 0.60 / paper 0.64, `--glass-bg-strong` 0.90 / 0.92 for surfaces whose job is to be read (detail card, tips, dialogs, the sheet when open), `--glass-blur` 16 px (12 on touch), `--glass-sat`, one top `--glass-sheen`, `--glass-edge` + `--glass-edge-low` as inset hairlines, `--glass-shadow`.
- **Mechanism** (`public/glass.css`): a surface opts in with `class="glass"` (+ `glass-strong`). Inside `@supports (backdrop-filter)` the class sets `--surface`, `--surface-image`, `--surface-blur`, `--surface-edge`, `--surface-shadow`; consumers read them with the solid `--surface-overlay` / `--surface-deep` as fallback. Styles that other scripts inject at runtime (export.js, map-i18n.js) are out-specified in `map-chrome.css` by rules that read the same properties.
- **Guards, all load-bearing:** no backdrop-filter → solid; `prefers-reduced-transparency` → solid; **moving-map freeze**: `body.interacting` and `body.map-moving` (set by `redraw()` while the view changes) switch the small chrome (controls, tips, cards) to the strong solid with blur off, easing back over `--t-base` when motion stops. **Exempt: `glass-steady`.** The phone sheet is `glass glass-mid glass-steady`: one material (`--glass-bg-mid`, 0.74 dark / 0.76 light, the weight of zhiyan's glaze) through peek, half, full, its own drag and any map gesture. Frozen glass at 0.90 with the blur off let 10 % of sharp map ghost through and read as *more* transparent than the blurred haze at rest, so touching the map or dragging the sheet visibly changed it (Yuyang, 2026-09-20). Three strengths exist: `glass` 0.60 (small chrome), `glass-mid` (the shell's header and footer, and the sheet: smoke `oklch(0.30 0.012 240 / 0.56)` dark, `oklch(0.97 0.006 85 / 0.60)` light), `glass-strong` 0.90 (menus, dialogs, detail cards). The mid tint is deliberately *lighter* than the map: at the dark 0.14 tint the bars measured indistinguishable from a solid slab over the dark ocean (luminance spread 3.6 vs 2.9 solid), so glass on a dark map must sit above the backdrop's brightness to be seen as glass (Yuyang, 2026-09-20 night).
- **Fixed bars (2026-09-20):** the shell's header and footer are `position: fixed` glass-mid on every page, so content and the map pass under them. Content pages pad by the measured bar heights (`--shell-top` / `--shell-bottom`, set on the shell's root by an inline script with a ResizeObserver; `html` gets a matching `scroll-padding-top`). On the map page the iframe is `position: fixed; inset: 0` beneath the bars; inside it, `map-mobile-sheet.js` measures each bar's overlap with the frame through the same-origin `frameElement` and publishes the same two variables on the iframe's root, and every edge-anchored piece of chrome adds them: the top-left row and zoom column (`+ --shell-top`), the region column, phone reset button, phone sheet, detail sheet, tips and keyboard hint (`+ --shell-bottom`), the legacy drawers (both), the desktop detail card (`top: --shell-top + 16px`). The phone sheet's half and full heights are fractions of the band between the bars, and the in-view rectangle starts below the header. Standalone `map-legacy.html` has no frame, so both variables stay 0 and nothing moves.
- **Never** a second accent, a glow, a gradient field, or glass on a chip.

## Motion (2026-09-20)
Tokens in `public/tokens.css`: `--t-fast` 120 ms, `--t-base` 200, `--t-slow` 280, `--t-flight` 450; `--ease-standard`, `--ease-enter`, `--ease-exit`. Every motion answers an action or explains a state change; nothing loops except the highlight pulse. `prefers-reduced-motion` collapses all of it: the map's JS animations run at 1 ms (`REDUCED_MOTION`), the CSS transitions are switched off, the arrival is skipped.
1. **Arrival, once per session** (`sessionStorage['sdl-arrived']`; on a first visit it waits for the welcome card to close): the camera arrives from 34° further west and 10° lower at 0.80×, flying in over 1.3 s with an ease-out while the continents resolve over 700 ms (the sphere is there at once); from 0.5 s discs and pins land nearest-the-centre first, 28 ms apart, each throwing one sonar ring (`.arrive-ring` / `.c-ripple`, 720 ms) while its count counts up; names are held until 1.9 s; chrome (`body.arriving`) fades in at 1.5 s with the sheet rising 28 px. The cluster cut is held at the destination scale during the flight so nothing splits mid-reveal. ≈2.4 s, and nothing a reader needs waits on it.
2. **Split and merge**: 250 ms travel-and-fade along the cluster tree (Phase 1).
3. **Flights**: region chips, disc taps and reset use `flyToView` / `flyTo`; long flights arc out and in.
4. **Control response**: press scales to 0.96 over `--t-fast`; pointer devices get a 1 px hover lift; focus-visible ring on every control.
5. **Phone sheet**: height moves on a JS spring (stiffness 320, damping 30) fed the release velocity; rubber band at a third past peek and full; a flick over 0.45 px/ms goes one state further. `--msheet-h` follows every frame so the reset button rides along. States: peek 112 px, half 52 svh, full 86 svh.
6. **Detail card**: desktop grows from 0.94 at the pin it belongs to (`--card-origin` set by `openSheet`); phone rises from the bottom with rows following 30 ms apart.
7. **Tips**: fade plus a 4 px rise over `--t-fast`.
8. **Theme flip**: glass surfaces and controls cross-fade colour over `--t-base`; the canvas repaints at once.
